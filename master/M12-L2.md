# M12-L2 – Register machine and instruction cycle {#L2}

**Course area:** M12 – Computer arithmetic and register machines

**Level:** Upper secondary (advanced level)

**Prior knowledge:** [M12-L1](M12-L1.md); [M1-L2](M1-L2.md); [M3-L2](M3-L2.md)

**Curriculum context:** Advanced-level extension based on Bavaria’s Grade 12 curriculum; not a nationwide uniform requirement.

## Learning objectives {#S1}

Explain the roles of memory, control unit, arithmetic unit and registers, trace an instruction cycle, distinguish direct from indirect addressing, and simulate a small program including branches and halt.

## Computer as a state machine {#S2}

A processor contains an arithmetic logic unit (ALU), a control unit and registers for temporarily needed values. The program counter (PC) indicates the address of the next instruction to fetch. The instruction register (IR) holds the current fetched instruction. The accumulator (ACC) stores a calculation result. A memory address register (MAR) can hold a memory address and a memory data register (MDR) the transferred data. Data, address and control signals connect components; input and output units connect the computer to its environment. In the von Neumann model program and data share memory. Modern computers may use separate caches and parallel processing stages, so the model does not describe every hardware detail. Our simulation separates an instruction list and data memory for readability; it is not a complete von Neumann computer.

## Fetch, decode and execute {#S3}

During fetch the model reads the instruction at PC and increases PC by 1. During decode the control unit identifies the operation and operand. During execute the instruction changes ACC, memory or PC, for example. A jump replaces the already incremented PC. A halt instruction stops execution. A machine instruction may take several clock cycles; the table’s steps are complete instructions, not individual hardware clock cycles. Memory contents, ACC and PC make up the observed state. Variables op and arg represent the instruction register in the simulation; MAR/MDR and buses are not modeled at clock-cycle resolution.

## Addressing and instruction set {#S4}

LOAD 10 loads M[10] into the accumulator. In LOADI 10, M[10] holds an address; M[M[10]] is the actual value. If M[10]=20 and M[20]=7, the two instructions return 20 and 7 respectively. ADD a adds M[a] to ACC modulo 256 (unsigned 8-bit data words). STORE a writes ACC to M[a]. JZ a jumps to instruction address a if ACC is zero, JMP a always jumps; HALT ends the program. Instruction and data addresses occupy separate namespaces here. Data are assumed to be words from 0 through 255, and used data addresses must exist in the dictionary. We do not store carry or overflow flags; only the defined modulo rule applies.

## Executable simulation {#S5}

The instruction list contains tuples of operation name and operand. Memory is a Python dictionary; copying it avoids side effects on the input. The trace records the old instruction address, operation, new PC and ACC. After LOADI 10, ACC=7; after ADD 21, ACC=12; after STORE 22, M[22] contains 12. HALT returns memory and the trace. Missing data addresses raise KeyError; an invalid PC or unknown instruction raises ValueError. An instruction limit prevents a test of an infinite loop from hanging. It does not prove that a program can never halt.

```python
def run(program, memory, limit=100):
    mem = memory.copy()
    acc, pc = 0, 0
    trace = []
    for _ in range(limit):
        if not 0 <= pc < len(program):
            raise ValueError("invalid PC")
        address = pc
        op, arg = program[pc]  # fetch and decode
        pc += 1
        if op == "LOAD":
            acc = mem[arg]
        elif op == "LOADI":
            acc = mem[mem[arg]]
        elif op == "ADD":
            acc = (acc + mem[arg]) % 256
        elif op == "STORE":
            mem[arg] = acc
        elif op == "JZ":
            if acc == 0:
                pc = arg
        elif op == "JMP":
            pc = arg
        elif op == "HALT":
            trace.append((address, op, pc, acc))
            return mem, trace
        else:
            raise ValueError("unknown instruction")
        trace.append((address, op, pc, acc))
    raise RuntimeError("instruction limit reached")


program = [("LOADI", 10), ("ADD", 21),
           ("STORE", 22), ("HALT", None)]
memory = {10: 20, 20: 7, 21: 5, 22: 0}
mem, trace = run(program, memory)
assert mem[22] == 12 and memory[22] == 0
assert [row[3] for row in trace] == [7, 12, 12, 12]
```

## Branches and model limits {#S6}

A sample JZ program can skip an addition depending on the accumulator: LOAD 30; JZ 3; ADD 31; HALT. With M[30]=0, JZ sets PC directly to 3 and ACC remains zero. With M[30]=2 and M[31]=5, execution passes through ADD and ends with ACC=7. The program state determines the next state change. With LOADI the indirect address can change during the program, permitting access to consecutive data without new LOAD instructions. Real processors have many more addressing modes, registers, interrupts and protection mechanisms. The model illustrates the logical sequence, but does not predict real clock rates or execution times.

## Self-assessment {#S7}

### Exercises

1. How do PC and IR differ?
2. What values do LOAD 10 and LOADI 10 produce in the example?
3. Trace PC and ACC after every instruction of the sample program.
4. What happens at ADD 21 if ACC=250 and M[21]=10?
5. Replace the program by LOAD 30; JZ 3; ADD 31; HALT. Compare traces for M[30]=0 and M[30]=2, with M[31]=5 in both cases.

::: {.lc-solutions data-lc-section="S7"}
1. PC identifies the next instruction to fetch; IR holds the current fetched instruction.
2. 20 and 7 respectively.
3. (PC,ACC): (1,7), (2,12), (3,12), (4,12). M[22]=12 from STORE onward.
4. 260 modulo 256=4; no flag is stored.
5. For 0: addresses 0,1,3; ACC=0. For 2: addresses 0,1,2,3; ACC=7.
:::
